# Selected floor import contract

The selected four-placement floor can retain its resource allocations and
layout bounds while changing its active geometry. The
[model path](floor-model-render-path.md) and
[visibility path](floor-model-visibility.md) identify the conditional native
consumers. These static findings define checks for an offline builder; they
do not qualify a visible or walkable floor.

## Selected inputs and method

The layout is `data/7F/1F/00/00.DAT`, 9,816 bytes, SHA-256
`c0a0e6128d36946ba32f8980ad80d39fd3aec990f3fc8a18742bbd8851a76b48`.
Its selected model is `data/7F/1C/00/00.DAT`, 41,088 bytes, SHA-256
`1af91b0e1e5e34f676f1af2884f82eddb63062e62bee058b0260e9646dfb7d0f`.
The retained authored model has the same size and SHA-256
`c567537529a31cbd1688102477972c8449e8a10cd3df29850c1e5fac9c95e160`.

Python `struct` and `hashlib` inspection compared these exact artifacts,
decoded their RES directory and WRB chunk tree, and checked every changed
byte. Importer behavior was inspected in
`xivl-tools:src/formats/src/model_import.rs` at revision
`75fe7414bf3f1ecd779825083d477adc4ed5f319`, specifically
`TemplateProfile::from_native`, `rewrite`, `replace_head`, `replace_bounds`,
`build_position_data`, `replace_stream_data` and `finish_chunk`.
This source inspection establishes the writer contract, not client behavior.
The linked native findings carry executable identities and instruction
locators independently of the importer.

## Fields owned by this edit

Offsets below are file offsets in this selected model, not VAs or RVAs.
The writer must derive them from the validated structure rather than accept
arbitrary caller-supplied offsets.

| Field | Selected authored value and constraint |
| --- | --- |
| MESH HEAD payload `+0x08/+0x0A` | Big-endian u16 vertex/triangle counts `4/2`. |
| Index STMS at `0x241C` | Big-endian item count `6`, stride `2`, active data at `0x244C`: indices `[1,2,0,1,3,2]`. Logical chunk size `60`, retained padded size `12336`. |
| Vertex STMS at `0x544C` | Big-endian item count `4`, stride `16`, active data at `0x549C`: `64` bytes. Logical chunk size `144`, retained padded size `18576`. |
| Vertex position lanes | Three big-endian i16 components at record `+0/+2/+4`, quantized against the updated bounds. Tile positions are `(-16,0,16)`, `(16,0,16)`, `(-16,0,-16)`, `(16,0,-16)`. |
| Vertex normal lanes | Three generated bytes at record `+8/+9/+10`, here `[128,255,128]`. |
| MESH AABB, MDL AABB and COMP | Six big-endian floats in each leaf body: minimum `(-16,0,-16)`, maximum `(16,0,16)`. The three chunk starts are `0x9CFC`, `0x9D4C`, `0x9D7C`; their ownership is detailed in the visibility finding. |
| Rebuilt chunk headers | Logical sizes must describe active data. For retained allocations, padded sizes must resolve to the original effective extents. The selected output normalizes four previously implicit padded-size fields without moving a chunk. |
| Selected layout resource IDs | Replace only the four-byte little-endian ID fields in the `22hJhCc0_00_p_h` rows: `brt` old ID `0x7F1C0000` and `bhp` old ID `0x7F200000`. Their selected offsets are `0x134/0x154`; row key, tag and expected old ID must match before writing. |

The model profile requires exactly one direct WRB, one MDL, one MESH, one
COMP, the required model/mesh AABB leaves, one supported position stream
and one supported index stream. Additional unsupported streams, ambiguous
or overlapping generated fields, nonrepresentable bounds and out-of-range
counts require refusal. The floor's zero Y extent encodes Y as zero.

## Bytes retained

Preserve the RES header and directory, resource order, allocation extents,
and every byte outside the selected WRB `[0x221C,0x9E8C)`. In this input the
last directory entry extends past EOF and overlaps another tail entry;
neither that relationship nor header `+0x34` has to be repaired to shrink
active streams. The edit retains them exactly.

Inside WRB, preserve chunk ordering and effective allocations, both unused
stream suffixes, stream descriptors/stride/flags, and all unowned payloads.
In each active vertex record preserve the fourth position component at
`+6/+7`, the fourth normal byte at `+11`, and the descriptor-selected field
at `+12..+15`. Copying these lanes preserves template data; it does not
establish their suitability for arbitrary new geometry or shader inputs.
Retain the material, shader, skeleton, opaque chunks and their references.

Preserve every layout byte outside the two selected ID words, including
the four placement transforms, folder bounds, resource keys, admission and
range flags, other resources and scene data. The selected placements keep
translations `(16,0,-16)`, `(16,0,16)`, `(-16,0,16)`, `(-16,0,-16)`.
The [visibility finding](floor-model-visibility.md) checks their expanded
native block bounds rather than requiring a change to hand-authored values.

The selected BGChip distance predicate consumes its owning BlockAABB.
Expanded folder containment is therefore the relevant offline culling-box
check for this profile. Preserve the placement and component transforms,
MINS node/mesh selectors, skeleton records, component mask inputs, material
names and resource paths, and PRAM bytes.
The [draw-tag trace](floor-model-render-path.md) connects these retained
material inputs to admission-state producers. Those runtime tag fields do
not add serialized fields to the importer's edit ownership.

## Offline acceptance

1. Authenticate the exact input bytes and validate the supported structure.
   Reparse outputs and check HEAD counts, STMS counts/strides, active data
   extents, index range and triangle-list divisibility together.
2. Check all three updated bounds and finite decoded positions. Transform
   each ordered render triangle through its preserved placement and compare
   it with that placement's authored collision triangle, including winding.
   This floor yields sixteen vertices and eight triangles spanning
   X/Z `[-32,32]` at Y zero.
3. Compare bytes outside the owned fields, including unused stream suffixes,
   opaque vertex lanes, the entire RES directory and the overlapping tail.
   Compare all chunk locations and effective allocations. The retained
   output has 22 unchanged chunk extents and exactly 57 changed bytes.
4. Derive the two layout ID offsets from parsed rows, verify the selected
   keys/tags and old IDs, reject collisions within the source table, and
   compare all other layout bytes. Inventory every nonzero direct resource
   row, including unplaced resources. This is not transitive dependency
   closure or proof that proposed IDs are unused in a client installation.

The byte comparison rejected deliberate mutations to the model prefix,
resource tail, unused stream suffix and fourth position component. It also
confirmed the retained marker layout changed only its two ID words.
The triangle comparison used the retained collision OBJ, 227 bytes,
SHA-256 `6975b553c44fabf5fb64e91dc1216489f6db05827eb32ad715fcfedf732fcf01`.
These are artifact checks, not a rerun of either writer or a client test.

## Native qualification boundary

Record successful resolution of the selected authored resource, the live
model/drawable/mesh identity, active buffer sizes and draw counts, placement
transform, component Joint output matrix, selected BGChip visibility
inputs/result and final draw admission in one attributable load. Correlate
the owning BlockAABB, transformed comparison point and effective distance
with that same placement. Record
tag `+0x118/+0xB0`, bytes `+0x131/+0x132` and `+0x1A` bits at dispatch,
then the final draw arguments and result. Device success and visible pixels
remain separate from a non-null resource or a true setup return. The two
native findings distinguish the remaining static caller edges from values
that need an attributable load.

Record model slot-30/32 calls from construction through dispatch with their
mask argument and drawable presence. Keep saved model `+0x294` separate
from applied tag `+0x131/+0x132`: saving a mask before a drawable exists
does not establish that it reached the later tags. The
[mask setup trace](floor-model-render-path.md#construction-and-setup-ordering)
owns the constructor, setter and initializer observations.

Preserving material and shader bytes does not establish their live variant,
bound textures, accepted vertex inputs or output appearance. A runtime check
must distinguish rejection before submission from a submitted draw producing
no visible floor. Collision standing and walking require their own evidence.
